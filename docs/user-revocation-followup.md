# 用户撤销与计费后续审计

本轮在本地回环环境检查用户热更新、已建立会话和流量归属。修复前的协议测试中，VMess 和 Trojan 的已建立 TCP、UDP 在删除用户后仍能转发；经典 Shadowsocks 已建立 TCP 也会继续转发。三者删除前的流量均从面板计数中消失。日志保留在 `.tools/legacy-revocation-before.log`。

| 路径 | 修正 |
| --- | --- |
| sing VMess、Trojan、经典 Shadowsocks 多用户 | 接入与 VLESS 共用的稳定认证记录和连接跟踪；撤销关闭父连接和已登记子会话。晚到路由必须通过同一代际检查才能取得计数器。 |
| VMess AEAD | 不可变认证服务会替换，因此额外保留跨快照的认证 ID 防重放窗口。用同一个真实 VMess 请求重放验证。旧本地 AlterID 配置仍由原实现处理。 |
| Trojan HTTPUpgrade | 无回落配置时，必须完整读取认证头才交给协议解析器。HTTPUpgrade 保留原有缓冲读，撤销只关闭其底层连接，避免同时修改缓冲区。 |
| Xray | 使用已注册的认证对象绑定连接。登记、取得计数器和撤销共享同一锁；上传结束后只要下载仍在运行就保留连接记录。撤销保存原 UID 的尾部流量。普通 `DispatchLink` 的上行读取也接入共享限速桶，并使用调用方给出的读取超时。 |
| 独立 Hysteria2 | 每个入站拥有自己的凭据表，删除后重加分配新内部身份。主动关闭已登记的 TCP 流；旧 UDP 在下一次数据传递时由 SDK 拒绝并断开。保留原 UID 计费。 |
| 面板用户列表 | 完整检查 JSON/MsgPack 快照、顶层用户字段及内容。截断、错误包裹、重复凭据和多余内容不提交 ETag，不当作空名单。原生流量 API 遇到同 UID 多行时累加。 |
| 限速与输入 | 动态限速到期只移除动态值，保留用户和设备配额；新连接重新按当前配置取桶。SS2022 过短密钥返回脱敏错误，不再截取越界。 |

## SS2022 与独立 Hysteria2

面板管理的 SS2022 多用户 AES-128/AES-256 入站，sing 和 Xray 都使用不可变认证快照。认证结果携带稳定用户对象，迟到的握手不能以已撤销用户发起路由。快照保留底层 TCP 盐值防重放和 UDP 会话状态；删除用户时关闭它的活跃路由，保留其最后一段计费。未纳入面板管理的本地静态、转接及托管入站仍沿用原有实现。

独立 Hysteria2 内核在转发 TCP/UDP 数据前消耗同一个用户限速桶，多个连接和上下行共用额度。等待额度不持有鉴权锁，撤销或关闭节点会取消等待，未转发的数据不会记账。同一条 QUIC 连接共享 UDP 读取路径，限速等待可能增加该连接内其他 UDP 会话延迟。

## 流量批次如何处理丢回执

升级 AriNode 节点和 XBoard 插件 0.9.3 后，普通节点通过受 XBoard `server.v2` 保护的接口自动协商批次回执，不需修改面板节点配置。新的流量不会合并进已发出的批次；超时或无回执时按原 ID、原数据重试。插件对同一节点的同批次只调用一次原生计费入口，已接收的重试直接返回回执；同 ID 换数据会返回 409。

接收确认表示原生计费入口已返回，不表示后台队列已入账。Redis 保存处理标记和回执，回执保留八天，请避免 Redis 淘汰并确保时钟同步。批次创建超过七天就不再接收。如果面板在派发途中发生错误，处理标记会保留，节点不会把该批次换 ID 或回退到原生接口。持续出现 409 时，应按节点日志的 `report_id` 核对 Redis 记录和面板队列；先确认已派发量再人工处理。该旧批次未确认前，新流量继续在内存累积。节点重启不保留内存批次，Redis 丢数据或原生队列自身重复执行也不在 HTTP 回执的保护范围。

无新接口的面板（探测返回 404/405）沿用原生 API；没有幂等键时无法区分已提交但回执丢失与未提交。旧版面板或只更新后端仍然可能重复计费。Cluster 使用其既有的合并接口与独立回执，本次未改变。

本轮用真实回环连接验证了两种 SS2022 AES 密钥长度在 sing 和 Xray 的 TCP、UDP 撤销、健康会话和原 UID 计数，另验证了用户刷新后旧 SS2022 TCP 密文不能重放。独立 Hysteria2 实测 TCP/UDP 双向限速、同账户共享、撤销取消等待和尾部计费；流量上报测试主动断开已提交请求的连接，确认重试 ID 和内容不变，插件恢复后新批次独立计费。PHP 测试另覆盖同 ID 改数据、过期批次、队列提交中途异常及接口鉴权配置；不等同于生产 Redis 和队列验收。
